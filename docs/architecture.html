Pokedex Architecture Diagram

Platform integrations, shared Kotlin Multiplatform (KMP) layers, and internal components

Platform Wrappers

  • Android Application: Written in Kotlin using Jetpack Compose UI. Bootstraps the application via `MainActivity` by calling Koin initialization and rendering `App()`.
  • iOS Application: Native Swift project utilizing SwiftUI. Loads the shared module through Swift Package Manager and wraps KMP's `MainViewController` inside a SwiftUI `ContentView`.
  • Web Application: Compiles to Wasm and Javascript. Bootstraps via `main.kt` by creating a `ComposeViewport` and running the shared `App()` code on HTML Canvas.

KMP Layer Separation

  • Presentation Layer: Entirely shared using Compose Multiplatform. Contains ViewModels and the `App.kt` routing structure driven by JetBrains Navigation 3.
  • Domain Layer: Pure Kotlin definitions. Contains data entities representing Pokedex entries and details, isolating repository implementation details.
  • Data Layer: Encapsulates all data access. The `PokemonRepository` mediates between domain models and remote network payloads returned by `PokemonRemoteDataSource`.

Dependency Injection & Network

  • Koin DI Setup: Instantiated through a common `initKoin` helper. Koin manages the lifecycles of ViewModels, repositories, and platform-specific implementations.
  • Infrastructure & Network: Utilizes Ktor Client with content negotiation and Kotlinx Serialization. Networking engines are selected per-platform (OkHttp on Android, Darwin on iOS, browser engines on Web).
  • expect/actual Config: Used to define platform-specific behavior for dependency bindings (`PlatformModule`) and custom database endpoints (`PlatformFirestore`).
